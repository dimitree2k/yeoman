# Review: Runtime/Source Structure Normalization

Reviewed 2026-09-07 against the plan, current source on `main`, and read-only systemd metadata. No implementation or service changes; no tests run. Gateway and Bridge were active; Overseer and Pinchtab were inactive. Existing tracked deletions under `.superpowers/sdd/` were left untouched.

Verdict: sound direction, revise migration rules before execution.

1. **P1 — Rollback loses post-cutover writes** (plan line 243). Restoring the prior state backup after production resumes discards subsequent session writes; restoring paths/config alone also leaves changed path-resolution code deployed. Define rollback before traffic resumes separately from rollback after new writes. Preserve/reconcile current state for the latter and record the compatible code revision, config and service units.
2. **P1 — Documentation task changes live configuration prematurely** (lines 126–130). Task 2 calls for updating every documentation/config reference and labeling all legacy paths inactive, before Task 5 migrates handles. `get_run_path()` still returns `var/run` in `packages/shared/yeoman_shared/utils/helpers.py:50`. Restrict Task 2 to accurate current-state documentation; defer config changes and retirement labels until each cutover.
3. **P1 — Handle migration omits a consumer and migrates stale process identities** (line 178). Overseer derives PID/socket/lock paths from `get_run_path()` and holds an exclusive flock (`packages/gateway/yeoman_gateway/cli/overseer_commands.py:25–54`). Include Overseer and restart-capable supervisors in the quiescence procedure, even though Overseer is inactive in this snapshot. Do not copy PID/lock/socket artifacts as durable state: verify old processes have exited and let the owning processes recreate handles. Include systemd daemon-reload when units change.
4. **P2 — Session-state migration uses the wrong storage contract** (lines 188–196). `SessionStateStore` is append-only Markdown, rooted at `workspace / state_dir`, not SQLite (`packages/gateway/yeoman_gateway/memory/session_state.py:11–20`). The default lives in `packages/shared/yeoman_shared/config/defaults.py:168`; the caller is `packages/gateway/yeoman_gateway/memory/service.py:102`. Specify a quiesced file copy with checksums and PRE/POST content preservation; define treatment of explicit absolute/relative stateDir overrides and alternate YEOMAN_HOME/workspaces. Do not describe this as SQLite WAL replay.
5. **P2 — var is incorrectly classified as regenerable** (lines 44–47). It includes logs and WhatsApp media, which cannot be assumed reconstructable. WhatsApp processing validates and reads local media paths, including quoted media (`packages/gateway/yeoman_gateway/channels/whatsapp.py:849–874,960–968`). Define var as variable runtime data; make only var/cache disposable by default and give media/logs explicit retention rules.

For maintainability, extend the existing ownership table with the owning component/writer, canonical resolver or config key, durability and deletion condition. A directory path is a location, not an owner. Keep Pinchtab decommissioning as a separate follow-up, since Task 7 requires removal while the deferred-decisions section permits continued use. Define a concrete recovery window before executing deletions.

Suggested scope: first documentation, backup naming and ownership rules; then separately verified handle and session-state migrations; finally the independent browser capability decision. Retain historical evidence rather than rewriting old snapshots to look current.
